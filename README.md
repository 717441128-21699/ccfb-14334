# 帘纹分析 · 古籍纸张断代辅助系统

通过透光图与反射光图的配准、扣墨与频域/空间域分析，自动测量纸张**帘纹间距、纲线间距、透光均匀度**，并对整本书的叶子做**同批纸聚类判定**。全部计算在浏览器本地完成（TypeScript + WebGL2），不上传图像。

## 测量流程

每片叶子按以下步骤处理（与人工在灯箱上数帘线的流程对应）：

1. **配准**：对透光图、反射图做 512² 降采样后用相位相关（含频域白化）求亚像素平移，反射图据此重采样对齐。
2. **扣墨**：反射图局部均值生成软墨掩码，Huber 稳健回归估计透光—反射关系，从透光图减去墨字/污渍影响，得到纸基本身的明暗。
3. **帘纹/纲线测定**：沿候选法线做旋转投影 + 自相关方向扫描，结合峰突出度与谐波一致性选出真周期，再抛物线插值到亚像素。频域 FFT 用于分量分离与诊断谱。
4. **频域分离**：高斯带通掩码 + 逆 FFT，分别画出帘纹分量、纲线分量。
5. **透光均匀度**：在残差（纸基减去周期分量）上计算均值、标准差、局部变异系数与梯度能量。
6. **档案**：每叶记录写入书册档案，按帘纹间距自然断点聚类，最大群组为主批次，其余标记为离群（疑似换纸）。

### 为什么帘纹以空间域自相关为主

旋转的周期纹理在离散像素栅格上会产生栅格化混叠，其高频能量在纯频域峰检测中可能强过真帘纹峰。而沿条纹法线的旋转投影自相关直接测量空间周期，对栅格化稳健；再用「峰突出度（压制低频趋势）+ 谐波一致性（真周期在 2P、3P 再现）」联合判据，可靠区分帘纹与云絮/纤维/笔画干扰。

## 目录结构

```
src/core/        纯数学参考实现（Node 可测，不依赖 WebGL）
  fft.ts         radix-2 FFT（含与朴素 DFT 对拍的测试）
  registration.ts 相位相关配准
  ink.ts         墨掩码 + Huber 稳健回归扣墨
  joint.ts       空间域帘纹/纲线自相关判定
  spectral.ts    频谱归一化、多候选峰、纲线剖面
  projection.ts  旋转投影与自相关精修
  uniformity.ts  透光均匀度
  synthetic.ts   合成测试叶子（含真值）
  archive.ts     档案与同批纸聚类
src/gl/          WebGL2 实现（与 core 数学等价）
  gl-context.ts  RG32F 浮点纹理封装
  gpu-fft.ts     位反转 + Cooley-Tukey DIT 蝶形 FFT
  shaders.ts     全部 GLSL 片元着色器
  gpu-pipeline.ts 主 GPU 流水线
src/ui/          无框架前端（五个标签页）
test/            Vitest 单元/端到端测试（CPU 参考）
e2e/             Playwright 浏览器测试（真实 WebGL2 对拍）
```

## 精度与性能（实测）

合成叶子（1024²，600dpi，四种帘纹密度 + 纤维等级 + 墨遮挡）：

| 预设 | 真值(mm) | 测量(mm) | 误差(mm) |
|---|---|---|---|
| 密帘纹-少墨 | 0.800 | 0.798 | 0.002 |
| 中帘纹-标准 | 1.400 | 1.397 | 0.003 |
| 疏帘纹-重墨 | 2.400 | 2.384 | 0.016 |
| 极密帘纹-无墨 | 0.550 | 0.551 | 0.001 |

均远优于 **0.1mm** 的设计目标。GPU 与 CPU 参考实现的 FFT 功率谱相对误差约 1e-5，帘纹测量一致；1024 工作尺寸单叶 GPU 耗时约 0.5s。原图仅在起始做一次降采样，后续 FFT/滤波在固定 1024² 或 2048² 上进行，因此分析耗时与原图分辨率基本无关，6000×8000 叶子同样满足 5 秒预算。

## 运行

```bash
npm install
npm run dev        # 打开 http://localhost:5173
npm test           # CPU 单元/端到端测试（18 项）
npm run test:e2e   # 真实 WebGL2 浏览器对拍（需 Playwright 浏览器）
npm run build      # 类型检查 + 生产构建
```

应用内含五个标签页：实叶分析（上传图）、合成验证（可交互演示与误差对照）、GPU/CPU 校验、性能计时、书册档案（JSON 导入导出）。

## WebGL2 实现要点

- 所有计算纹理统一用 **RG32F**：WebGL2 规范中 R32F 的可渲染性是可选的（部分 ANGLE/AMD 驱动不支持将其作为渲染目标），而 RG32F 在 `EXT_color_buffer_float` 下强制可渲染。
- GPU FFT 采用**位反转预处理 + 迭代 Cooley-Tukey DIT 蝶形**多 pass，正变换不归一化（与 CPU 参考一致），二维逆变换的 1/N² 归一化在频域滤波着色器中按每方向 1/N 处理。
- 读回纹理前需重新绑定对应 framebuffer，避免前序 pass 切换渲染目标后读到错误缓冲。
